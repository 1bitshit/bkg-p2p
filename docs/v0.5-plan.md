# bkg-peer v0.5 — Engineering plan (living document)

This document **extends** the roadmap summary in the root [README.md](../README.md). Update it as scopes change; use it to open issues and track acceptance criteria.

**Baseline:** v0.3 in-tree — agent runtime (ReAct loop, budget, tool execution), crew + flow orchestration, P2P crew market, provider sharing, agentic web path, externalized `prompts/*.txt`, job marketplace, wallet/escrow, WASM sandbox, safety layer, MCP, vector memory, skills, swarm visualization, Ed25519 signatures, Rustyline CLI, diagnostics (`bkg-peer doctor`).

## Completed (v0.3 → v0.4 → current)

The following items have shipped and are **not** v0.5 blockers:

- **Agent runtime** — ReAct loop with tool calling, budget enforcement (per-request/hour/day/total), TOML-defined agent specs
- **Crew + Flow orchestration** — `src/crew/{spec,orchestrator,store,p2p}.rs`, `src/flow/{mod,interpreter}.rs`; in-memory run stores; P2P crew market via GossipSub `bkg-peer/crew/v1`
- **Workflow builder** — Visual node editor in web dashboard (pill-style nodes, library browser, hover-delete)
- **Multi-step agent templates** — Deep Researcher, Code Reviewer, Creative Writer, Data Analyst in `templates/flows/`
- **LLM provider sharing** — Advertise Ollama/GGUF models on P2P; remote single-shot inference with escrow billing
- **WASM sandbox** — `src/wasm/{sandbox,fuel,host}.rs`; Wasmtime with explicit capability grants (log, time, random, I/O)
- **Safety layer** — Leak detection, prompt injection defense, content policy enforcement, SSRF guard, egress filtering (`src/safety/`)
- **MCP integration** — `src/mcp/`; stdio + HTTP servers, in-memory config, web console
- **Swarm visualization** — D3.js topology, agent cards, event timeline (`src/swarm/`, `/api/swarm/*`)
- **Ed25519 signatures** — Cryptographic identity on all P2P messages
- **Rustyline CLI** — Tab completion, history, arrow keys for `bkg-peer chat`
- **Diagnostics** — `bkg-peer doctor` with 10 subsystem checks
- **Python SDK** — `sdk/python/` with validate + kickoff + poll examples
- **A2A integration** — JSON-RPC task interface, agent cards, GossipSub peer discovery
- **Real-time streaming** — WebSocket + SSE for agent runs, chat, workflow progress
- **Prompt customization** — `prompts/*.txt` overlays, `[prompts].directory` config + `BKG_PEER_PROMPTS_DIR` env
- **Reputation module** — `src/reputation/{types,trust,scorer,store}.rs`; peer trust levels, off-chain rolling success rate
- **Inference distribution** — `src/inference/distribution.rs`; pipeline parallelism scaffolding
- **Routines engine** — `src/routines/`; cron, heartbeat, startup/event-triggered tasks
- **Documentation agent** — `src/documentation/`; skill doc generation, caching, audit trail
- **Agent library** — `src/agent_library.rs`; saved workflow/agent specs with web CRUD
- **Observability** — `src/observability/`; tracing spans, metrics, optional OTLP export

**Release intent for v0.5:** Seal the current surface as a **stable, productized** multi-agent + P2P mesh: durable runs with resume, observability maturity, HITL for risky tool calls, productized context compaction, and a credible (feature-flagged) path to multi-node inference.

## 4. Phase 1 — Run spine: observability + durability

**Status: MOSTLY IN-MEMORY; redb tables exist but runs are not persisted yet**

`src/db/mod.rs` has tables: `peers`, `wallet`, `agents`, `tools`, `settings`. No `runs` or `run_events` tables yet. `CrewRunStore` / `FlowRunStore` are in-memory. `WebTask` state lives in `WebState` + SSE events only.

### 4.1 Unified run model (design)

Define a generic **`RunRecord`** (or per-kind tables with shared envelope):

- `run_id`, `kind` (`agent_task` | `crew` | `flow`), `status`, `created_at`, `updated_at`
- `spec_fingerprint` (hash of canonical JSON), `inputs_redacted` (no secrets)
- `events: Vec<RunEvent>` append-only

**`RunEvent` examples:** `pass_started`, `pass_completed`, `tool_started`, `tool_completed`, `inference_completed`, `error`, `cancelled`, `checkpoint_saved`

## 5. Phase 2 — Distributed inference

**Status: SCAFFOLDING EXISTS** — `src/inference/distribution.rs` present, v0.4 shipped provider sharing (remote single-shot with escrow). Full tensor parallelism is **out of scope** for v0.5.

**Goal:** A **documented protocol** and a **working 2-peer pipeline path** (peer A runs layers 0..k, peer B runs k..end) behind `config.inference.distributed_pipeline`, with timeout + fallback to local single-peer inference.

### Work packages

| V05-2-03 | **Metering** | Charge BKG per sub-request; integrate with `Wallet` / economy config; bill requester for both hops |

## 7. Phase 4 — Human-in-the-loop (HITL)

**Status: SCAFFOLDING EXISTS** — `src/safety/` has policy, validator, task scanner. Unified loop can be instrumented to pause. State machine and API are **not yet implemented**.

**Goal:** When policy says “high risk”, tool execution **blocks** until approved via API (and UI), with timeout and audit entry on Phase 1 spine.

### Policy sources (v0.5)

- Tool name patterns (`shell`, `file_write`, `code_exec`)
- Agent spec TOML: `[hitl] tools = ["shell"]` or spend threshold
- Global `config.toml` defaults: `[safety] hitl_enabled = true`

### Work packages

| ID | Task | Acceptance criteria |
|----|------|---------------------|
| V05-4-01 | **State machine** | `pending_approval` → `approved` \| `rejected` \| `expired`; stored in `redb` |
| V05-4-02 | **API** | `GET /api/approvals`, `POST /api/approvals/:id/approve`, `…/reject`, `…/expire` |
| V05-4-03 | **Wire unified loop** | Block `ToolRegistry::execute_local` path when approval missing; timeout with configurable TTL |
| V05-4-04 | **Web UI** | Queue panel + reason + tool args preview (redacted by `SafetyLayer`) |
| V05-4-05 | **Tests** | Timeout path releases lock; no double-execution; test with `shell` tool |

## 8. Phase 5 — Context compaction (productized)

## 10. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| Scope creep on distributed inference | Ship protocol + 2-peer demo behind flag; defer wide acceleration |
| redb migration pain | Version tables; optional “export JSON” before upgrade |
| HITL deadlocks | Always-on timeout; executor thread pool isolation |
| OTLP noise | Default off; sample rate config |
| Compaction quality | LLM summaries may hallucinate; keep `truncate` as safe default; log compaction events |
| Cross-peer tool trust | Require minimum reputation score; escrow lock before execution |
